## Function Description

SubMulConcat is an internal fusion operator. It is generated by the existing CANN graph fusion process that fuses the original graph composed of Sub, Mul, and Concat/ConcatV2/ConcatV2D. The operator has no public ACLNN API and does not support directly constructing SubMulConcat nodes.

- `[general]` This directory retains the internal OpDef and InferShape, which are used only for internal nodes after graph fusion. Fusion rules are not delivered this time, and no public REG_OP or ACLNN API is added.
- `[existing]` The Ascend910B implementation corresponding to Atlas A2 continues to be maintained in canndev. Its arch32 Tiling, Kernel, or UT is not migrated to this directory this time.
- `[RegBase-native]` This directory adds and delivers only the arch35 Host Tiling and RegTensor-based Kernel implementation of Ascend950.

For the inputs $x$ and $y$ that are both of the float32 data type, both in the ND format, and both with the shape $[N,H,W]$, the computation formula is as follows:

$$
z = \operatorname{Concat}\left([x,\ y,\ x-y,\ x\odot y],\ \mathrm{axis}=-1\right),
\qquad z\in\mathbb{R}^{N\times H\times 4W}.
$$

Here, $\odot$ denotes element-wise multiplication.

## Constraint Description

- The inputs `x` and `y` support only the FLOAT data type and the ND format, and must be three-dimensional tensors $[N,H,W]$ with the same shape.
- Under the existing graph fusion rules, the original graph must concatenate the 4 inputs in the order of `x`, `y`, `x-y`, and `x*y`, and the concatenation axis of Concat/ConcatV2/ConcatV2D must be -1 or 2.
- The internal node accepts only `axis` values -1 and 2; other values are rejected by InferShape.
- In dynamic shape scenarios, input dimensions may use the unknown-dimension descriptor -1. An unknown last dimension is not multiplied by $4 \times W$ and is preserved as is. The unknown-rank descriptor -2 is not part of this operator's rank-3 input contract and is rejected by InferShape.
- The outputs of Sub and Mul can be consumed only by this concatenation node. Otherwise, the existing graph fusion rules will not generate the SubMulConcat node.
- SubMulConcat is generated only by the existing graph fusion process. It has no public ACLNN API and does not support directly constructing its internal nodes.
