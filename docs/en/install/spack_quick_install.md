# Quickly Set Up a Development Environment with Spack

<!-- md-trans-meta sourceCommit=unknown translatedAt=2026-11-17T12:36:50.900Z pushedAt=2026-11-18T07:58:22.370Z nl=2 -->

New developers can quickly set up a development environment by following the steps below.

## 1. Local Quick Build

### 1. Quickly Set Up the Environment Locally and Build

#### Method 1: Run the One-Click Script for a Quick Build

prepare_cann_env.sh sets up the Spack environment and installs all dependencies of ops-math in one click.

```bash
# Enter the code root directory
cd ${local_repo_path}/ops-math
source spack/prepare_cann_env.sh
```

#### Method 2: Manually Configure the Environment (for Advanced Users or Custom Configurations)

To control the environment configuration more precisely, configure it manually as follows:

##### Step 1: Download and Install Spack (Skip If Spack Is Already Installed)

```bash
# Select the installation directory (default: $HOME)
export SPACK_INSTALL_DIR="$HOME"
# Download Spack v1.1.0 and activate the Spack tool
cd $SPACK_INSTALL_DIR
git clone https://gitcode.com/GitHub_Trending/sp/spack.git -b v1.1.0 --depth=2
source $SPACK_INSTALL_DIR/spack/share/spack/setup-env.sh
# Verify the Spack version after installation
spack --version
```

##### Step 2: Set the Default Installation Path for Spack Packages

The default installation path for Spack packages is $SPACK_INSTALL_DIR/spack/opt. Change it with the following command:

```bash
# Regular user
spack config --scope user add "config:install_tree:root:$HOME/.spack"
# root administrator
spack config --scope system add "config:install_tree:root:/opt/spack"
```

Regular users are advised to use a directory under their home directory to avoid instability caused by other users modifying the environment.
Administrators are advised to use a global path to install software uniformly for other users through [Spack chaining](https://spack.readthedocs.io/en/latest/chain.html):

##### Step 3: Add Externally Installed Tools to the Spack Environment

```bash
spack compiler find  # Configure locally installed compilers, such as gcc
```

##### Step 4: Configure the GitCode Mirror for the Official Spack Repository

The default official Spack repository is the [Spack GitHub repository](https://github.com/spack/spack-packages). Change the default official repository to the GitCode mirror for acceleration as follows:
Modify repos.yaml in the ~/.spack directory. If it does not exist, create the file and write the following content:

```yaml
repos:
  # Spack built-in repository
  builtin:
    git: https://gitcode.com/spack/spack-packages.git
    branch: releases/v2025.11
```

Verify the repository configuration: `spack repo list`

##### Step 5: Download and Add the CANN Community Spack Package Repository

```bash
# Clone the CANN Spack package repository
cd $SPACK_INSTALL_DIR
git clone --depth=1 https://gitcode.com/cann/cann-spack-package.git

# Add it to the Spack repository list
spack repo add $SPACK_INSTALL_DIR/cann-spack-package

# Verify that it is added successfully
spack repo list | grep cann
```

##### Step 6: Create and Activate a Spack Environment

```bash
# Create an environment named cann-dev-env
spack env create cann-dev-env ${local_repo_path}/ops-math/spack/spack.yaml

# Activate the environment
spack env activate cann-dev-env

# Verify that the environment is activated
spack env status
```

##### Step 7: (Optional) Configure Automatic Loading in the Terminal

```bash
# Add the Spack environment configuration to .bashrc
echo "source $SPACK_INSTALL_DIR/spack/share/spack/setup-env.sh" >> ~/.bashrc

# Make it take effect immediately
source ~/.bashrc
```

##### Step 8: Configure Development Mode and Install

```bash
# Set ops-math to development mode (pointing to the local code)
spack develop -p ${local_repo_path}/ops-math cann-ops-math@master

# Add the package to the environment (adjust variants as needed)
spack add cann-ops-math@master+pkg+jit

# Resolve dependencies
spack concretize -f

# Install
spack install
```

### 2. View the Output Location

Run the command

```bash
spack location -i cann-ops-math
```

to view the location of the run package generated by compiling ops-math. The run package is automatically installed under ASCEND_HOME_PATH.

## 2. Rebuild After Modifying Code

### 1. Uninstall the Built Output

```bash
spack uninstall -y cann-ops-math
```

### 2. Remove Existing Variants and Add New Variants

To specify different build parameters, change the Spack package variants.
(Skip this step if the build parameters are unchanged.)

```bash
spack change cann-ops-math@master +pkg +jit soc=ascend910b # Example
```

### 3. Resolve Dependencies Again

```bash
spack concretize -f
```

### 4. Rebuild

```bash
spack install
```

## 3. Re-enter the Spack Environment

A new terminal requires re-entering the Spack environment.

```bash
spack env activate cann-dev-env
```

## 4. Clean Up the Environment or Uninstall Spack

To stop using Spack, use the clean parameter of `prepare_cann_env.sh` to uninstall Spack and **restart the terminal** to clean up environment variables.

```bash
source spack/prepare_cann_env.sh clean
```

## 6. Spack Development and Debugging Command Guide

```shell
# View the current environment list: if generated by the one-click script prepare_cann_env.sh, the development environment cann-dev-env is ready
spack env list

# Create an environment: environments managed by Spack are isolated from each other and associated with packages through links
spack env create <env-name>

# Activate an environment: the currently activated environment is shown in green, and Spack commands apply to the currently activated environment regardless of location
spack env activate <env-name>

# View the packages introduced in the current environment: if not run in a specific environment, all environments are shown
spack find                              # List all packages
spack find -L                           # Show full hashes
spack find <package-name>               # Filter by package name; all packages if not provided
spack find --deps <package-name>        # Show the dependency tree of the package
spack find --explicit <package-name>    # Show manually installed top-level packages; abbreviation: -e
spack find -p <package-name>            # Show the full installation path
spack find -lv <package-name>           # Show full hashes and variant information

# Add a package to the current environment:
spack add <package-name>                # Also support spec syntax to specify version, variants, compiler, etc.

# Remove a package from the current environment: Spack does not delete the package; it only removes the dependency between the current environment and the package
spack remove <package-name>

# Uninstall a package: Spack can uninstall it only when no Spack environment depends on it; this uninstalls the locally installed package. Use it with caution
spack uninstall <package-name>

# Delete a Spack environment: physically delete files. Use it with caution
spack env remove <env-name>

# Deactivate the current environment:
spack env deactivate

# Search for packages supported by Spack
spack list <package-name>
spack list 'py-*'        # List all Python packages
spack list -d 'mpi'      # Search for mpi in descriptions

# View available version numbers
spack versions <package-name>

# Clear the Spack build cache:
spack clean
spack clean --all   # Clear all old source code, old build records, and caches. Use it with caution

# View current package information: view all supported versions of the package; Spack prefers the latest version by default
spack info <package-name>

# Install a package; Spack automatically selects the latest version
spack install                                                   # Install all uninstalled packages in the current environment
spack install <package-name>                                    # Specify a specific package name
spack install <package-name>@1.12.0%gcc@11.4.0                  # Spec syntax to specify version and compiler version
spack install <package-name>+mpi+fortran ^openmpi@4.1           # Spec syntax to specify variants
spack install <package-name1> <package-name2> <package-name3>   # Install multiple packages at the same time
spack -k install                                                # Skip security authentication during installation, use with caution
spack install --verbose                                         # Output detailed build logs; abbreviation: -v
spack install --no-checksum                                     # Disable network checksum verification during installation. Use it with caution

# Concretize the current environment: Spack prefers to reuse locally installed packages by default, even if a higher version satisfying the dependencies exists, unless the local package no longer meets the dependency conditions
spack concretize

# Download package source code from the remote to the local and register it as a development package: otherwise the remote files referenced by Spack are used as temporary cache files and are cleared by spack clean
spack develop <package-name>

# Register a development package from the local code development directory
git clone <git-path>  # Clone the source code and enter the directory
cd /package/path
spack develop --no-clone <package-name>

# Resolve the dependency information of the package:
spack spec <package-name>

# If the git repository is updated, this command synchronizes updates based on the remote repository address and branch configured in repos.yaml
spack repo update <repo name>

# Locate the package installation location:
spack location -b <package-name>

# View compiler configuration:
spack compilers                                                 # View all supported compilers, same as spack compiler list
spack compiler add /path/to/compiler/bin                        # Manually add a compiler

# View locally installed software reused by Spack
spack external find

# View the Spack version and verify the installation:
spack --version

# Edit Spack configuration: vim opens automatically
spack config edit config
spack config edit packages
```

## 8. FAQ

### 1. What to Do If prepare_cann_env.sh Reports an Error?

If Spack was previously installed on the machine, environment variables or configuration files may remain. Back up critical data, run ```source spack/prepare_cann_env.sh clean```, restart the terminal, and then run it again.

### 2. What to Do If an SSL Error Occurs During Installation?

This error occurs because the machine lacks the relevant certificates. Configure the certificates and run it again.

### 3. How to Uninstall Spack If It Is No Longer Needed?

Run ```source spack/prepare_cann_env.sh clean``` to uninstall Spack automatically. The root user also needs to run ```rm -rf /opt/spack``` to uninstall all Spack packages.
